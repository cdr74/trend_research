# ADR 0017: JSON Data Bundle Exporter and Interactive Web Dashboard

## Status
Accepted

## Context
Milestone 4 of the Trend Horizon Radar project transitions the system from core intelligence gathering and adversarial evaluation into executive presentation, data exchange, and interactive exploration.

Decision makers (QA Directors, Principal Test Architects, Enterprise Security Gatekeepers) require rich visual and analytical tools to explore evaluated innovations. Specifically:
1. **Interactive Multi-Perspective Visualization:** Users need to switch between four distinct operational lenses:
   - *Radar Quadrant View:* Standard 4-ring radar (Adopt, Trial, Assess, Hold) divided into the 6 Quality Engineering (QE) categories with interactive blips and tooltips.
   - *Matrix Table View:* Tabular comparison grid with sortable columns, risk badges, and expandable skeptic critique dossiers.
   - *Scatter Matrix View:* Two-dimensional scatter plot comparing Viability Score (Y-axis) versus Hype Score (X-axis) across 4 quadrant zones (e.g., "High Viability / Low Hype" sweet spot vs. "Marketing Traps").
   - *Semantic Cluster View:* Two-dimensional spatial projection of high-dimensional semantic embeddings (from `pgvector`) to visualize topical proximity, sub-domain clusters, and parasitic wrapper overlap.
2. **Standardized Data Exchange Contract:** The CLI exporter (`radar export --format json`) must produce a versioned, self-contained `RadarData` JSON document containing metadata, ring definitions, categories, and evaluated item records with 2D projection coordinates (`cluster_x`, `cluster_y`).
3. **Flexible Free-Format Querying:** Users must not be restricted to rigid UI dropdowns or command-line flags. Both the CLI and Web UI must support free-format querying:
   - *Web Dashboard:* A unified search Omnibar supporting plain-text full-string search combined with structured token parsing (e.g., `ring:Adopt viability:>0.80 tier:oss "visual testing"`).
   - *CLI Operations Tool:* Free-text semantic similarity search (`radar query "<natural language query>"`) and direct ad-hoc SQL querying (`radar query --sql "<SQL>"`).

## Options Considered

### 1. Dimensionality Reduction Topology for Semantic Clustering
- **Option 1A: UMAP (`umap-learn`) (Selected):**
  - Uses Uniform Manifold Approximation and Projection to reduce 1536-dimensional or 768-dimensional text embeddings down to 2 dimensions.
  - *Pros:* Superior preservation of both local metric neighborhood and global manifold clustering relative to PCA or t-SNE; clearly isolates parasitic wrapper tools and clusters related research topics. Prebuilt wheels are readily available for Python 3.12 on Linux/WSL and GitHub Actions runners.
  - *Trade-offs:* Requires $N \ge 4$ data points to construct k-nearest neighbor graphs; requires a graceful fallback (such as deterministic PCA or normalized grid distribution) if item count is small or manifold graph cannot resolve.
- **Option 1B: Standard Linear PCA via SVD:**
  - Fast, deterministic, zero additional dependencies.
  - *Trade-offs:* Linear projection cannot unroll complex non-linear semantic manifolds, leading to crowding in the center of the 2D plane.
- **Option 1C: Client-Side Browser Projection (e.g., t-SNE in JS):**
  - Run projection on the fly in the browser.
  - *Trade-offs:* Non-deterministic between page loads, high CPU burden on the user's browser, and cannot be exported into static `radar.json` for external downstream consumers.

### 2. Free-Format Query Architecture in the Web UI
- **Option 2A: Hybrid Omnibar with Token DSL Parser (Selected):**
  - A single search input in the header/sidebar that parses token key-value filters (`ring:`, `category:`, `tier:`, `viability:>X`, `hype:<Y`, `stage:`, `risk:`) alongside free-text keyword substrings.
  - *Pros:* High user ergonomics matching industry standards (GitHub, Jira, Gmail). Non-blocking, pure client-side execution with instantaneous reactivity across all 4 visual views. Works in harmony with the visual sidebar checkboxes and sliders.
  - *Trade-offs:* Requires robust client-side token parsing logic that handles quoted phrases and numerical inequalities cleanly.
- **Option 2B: Full SQL / DuckDB-Wasm in Browser:**
  - Embed DuckDB-Wasm in the browser application.
  - *Trade-offs:* 15-20MB WASM bundle overhead, steep learning curve for non-technical leadership reviewing the radar.

### 3. Web Dashboard Architecture
- **Option 3A: Decoupled Single Page Application (Vite + React + Tailwind + SVG/Canvas) (Selected):**
  - Decoupled in `web/`, consuming the static `radar.json` bundle generated by `radar export`.
  - Responsive, dark-themed, high-contrast UI tailored for enterprise architects.
  - *Pros:* Fully portable, zero server runtime dependency, deployable to GitHub Pages or static S3/GCS buckets.
- **Option 3B: Server-Side Rendered Python Dashboard (Streamlit / Dash / Shiny):**
  - *Trade-offs:* Requires a running Python container/server, lacks fine-grained visual animation and SVG interactive controls.

## Decision Rationale
1. **UMAP with Deterministic SVD Fallback:**
   We adopt `umap-learn` as the primary 2D dimensionality reducer in `src/radar/presentation/projection.py`. For small sample sizes ($N < 4$) or single-point evaluations, the projection engine falls back gracefully to deterministic Singular Value Decomposition (SVD PCA) or center-normalized offsets, ensuring the pipeline never fails or throws exceptions regardless of dataset size.
2. **Unified Omnibar with Token Parser:**
   We implement a client-side tokenizer in `web/src/utils/tokenSearch.ts` supporting:
   - Ring: `ring:Adopt`, `ring:Trial`, `ring:Assess`, `ring:Hold`
   - Category: `category:"Test Synthesis"`, `category:Execution`
   - Evidence Tier: `tier:Academic`, `tier:oss`, `tier:post-mortem`, `tier:vendor`
   - Numerical thresholds: `viability:>0.8`, `viability:<0.5`, `hype:>0.4`, `hype:<0.2`
   - Lifecycle stage: `stage:Emerging`, `stage:Consolidated`, `stage:Fading`
   - Free text: `"exact phrase"` or general keywords matching names, innovations, risks, and prerequisites.
3. **Four First-Class Presentation Views:**
   - `RadarChart.tsx`: 4 polar rings with quadrant labels and animated blips.
   - `TableView.tsx`: Searchable data matrix with risk badges and skeptic audit logs.
   - `ScatterPlot.tsx`: Hype vs. Viability quadrant chart with dynamic threshold lines.
   - `ClusterMap.tsx`: 2D semantic projection canvas with cluster proximity rings and wrapper indicators.

## Consequences

### Positive
- Delivers an enterprise-grade visual intelligence tool that can be used either completely offline via static build (`web/dist/`) or served locally.
- Free-format token search empowers power users to filter complex criteria in seconds without repetitive clicking.
- Semantic clustering provides an intuitive visual way to spot redundant tools and wrapper technologies.
- The `RadarData` JSON export format is fully compatible with third-party visualization tools or external reporting scripts.

### Negative / Trade-offs
- `umap-learn` introduces scientific Python dependencies (`numba`, `scipy`, `scikit-learn`) into the project environment, which are now managed deterministically via `uv`.
- UMAP coordinate spaces are relative to the current dataset batch; incremental runs should preserve consistent scaling (`[-1.0, 1.0]`).
